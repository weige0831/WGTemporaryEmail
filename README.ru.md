# WGTemporaryEmail

Одноразовая временная почта с приоритетом конфиденциальности, с возможностью самостоятельного хостинга.

**Демо-сайт: [https://mail.twcdk.com](https://mail.twcdk.com/)** · Справочник API: [https://mail.twcdk.com/api](https://mail.twcdk.com/api) · Панель управления: `https://mail.twcdk.com/admin`

WGTemporaryEmail собран на основе двух отличных open-source проектов и расширен до полноценного продукта, готового к эксплуатации:

| Исходный проект | Роль | Расширения в этом проекте |
|---|---|---|
| [Lm36/tempmail-server](https://github.com/Lm36/tempmail-server) | Бэкенд (FastAPI API + MX-сервер на Go + PostgreSQL) | API управления (`/api/v1/admin/*`) и панель управления, мастер первичной настройки, горячая перезагрузка конфигурации, горячая перезагрузка MX, лимит хранилища с автоочисткой, исправления ошибок (например `max_emails_per_address` был захардкожен), усиление безопасности |
| [Lm36/mailbucket](https://github.com/Lm36/mailbucket) | Пользовательский фронтенд (Next.js 15) | Интеграция в `web/`, same-origin вызовы API, статический экспорт через nginx, панель управления на китайском `/admin`, мастер `/setup`, санитизация XSS (DOMPurify), i18n на 16 языков |

Все проекты распространяются под лицензией MIT, оригинальные уведомления об авторских правах сохранены. Спасибо [Lm36](https://github.com/Lm36) за отличную работу.

## Возможности

- **MX-сервер, совместимый с RFC** - принимает почту от любого провайдера на порту 25
- **Пользовательский фронтенд** - входящие, вложения, скачивание исходного письма, бейджи DKIM/SPF/DMARC, тёмная тема
- **Панель управления** (16 языков) - статистика, управление письмами/адресами/доменами, горячее обновление конфигурации, ручная очистка
- **Мастер первичной настройки** - настройте домены, имя хоста, токен администратора и домен панели прямо в браузере
- **Автоматизация Let's Encrypt** - выпуск в один клик из панели, автоматическое продление; MX и HTTPS панели используют один сертификат, продление не требует перезапуска MX
- **Контроль хранилища** - лимит `max_storage_mb`, самые старые письма удаляются автоматически; также есть лимит писем на адрес
- **Контроль доступа** - привяжите домен панели и запретите доступ к пользовательскому сайту по IP/другим доменам; панель управления и API всегда остаются доступными
- **Безопасность** - ограничение частоты запросов, санитизация XSS, SQL через ORM, сравнение токенов за постоянное время, контейнеры без root, обязательный пароль БД, никаких слабых значений по умолчанию
- **16 языков** - English, 简体中文, 繁體中文, 日本語, 한국어, Español, Français, Deutsch, Português, Русский, العربية (RTL), हिन्दी, Italiano, Türkçe, Bahasa Indonesia, Tiếng Việt

## Архитектура

```
Интернет
  │
  ├─ :25  ───────────────► mx     (SMTP на Go, горячая перезагрузка config.yaml каждые 15 с)
  │
  └─ :80 / :443 ────────► web    (nginx: статический фронтенд + обратный прокси)
       ├─ /                  пользовательская панель (16 языков)
       ├─ /admin             панель управления (16 языков)
       ├─ /setup             мастер первичной настройки
       ├─ /api/* ──────────► api    (FastAPI, только внутренняя сеть)
       ├─ /docs, /openapi.json ──► api    (Swagger)
       └─ /.well-known/acme-challenge/  (для sidecar certbot)
            │
            └──► postgres (только внутри)
```

- `api` и `postgres` не публикуют порты на хост; всё идёт через nginx.
- Sidecar `certbot` выпускает и продлевает сертификаты через HTTP-01 webroot; `web` автоматически перезагружает nginx при изменении сертификата или конфигурации.

## Развёртывание

### Требования

- Домен с доступом к DNS (MX-запись обязательна для приёма почты)
- VPS с публичным IP; порты **25** и **80** доступны (443 для HTTPS панели)
- Docker + Docker Compose, около 1 ГБ ОЗУ (на маленьких VPS добавьте swap), несколько ГБ диска

### Вариант A: интерактивный скрипт установки

```bash
git clone https://github.com/weige0831/WGTemporaryEmail.git
cd WGTemporaryEmail
./setup.sh
```

Скрипт спросит домены приёма, имя хоста почты, веб-порт, CORS и параметры TLS, сгенерирует `config.yaml` (со случайным токеном администратора) и `.env`, выведет DNS-записи и выполнит `docker compose up -d --build`.

### Вариант B: ручная настройка

```bash
git clone https://github.com/weige0831/WGTemporaryEmail.git
cd WGTemporaryEmail
cp config.yaml.example config.yaml
cp .env.example .env
# 1) отредактируйте config.yaml: domains, server.hostname, admin.token, пароль БД
# 2) отредактируйте .env: DB_PASSWORD (обязательно), WEB_PORT (по умолчанию 80)
mkdir -p certs
docker compose up -d --build
```

При первом посещении откроется **мастер /setup** (в примере `setup.initialized: false`) — введите те же значения в браузере.

### DNS-записи

```
mail.ваш-домен.  IN  A    <IP сервера>      # имя хоста почты
ваш-домен.       IN  MX  10 mail.ваш-домен.
```

Также попросите VPS-провайдера настроить обратный DNS (PTR) IP сервера на `mail.ваш-домен`.

### Включение TLS / HTTPS панели

1. Панель управления → Настройки → Домен доступа к панели: укажите, например, `mail.ваш-домен` и направьте его A-запись на сервер в DNS
2. Карточка TLS-сертификата → введите email → **Выпустить / продлить сертификат** (SAN-сертификат покрывает имя хоста почты и домен панели)
3. Включите `tls.enabled` — MX сразу запускает STARTTLS (без перезапуска)
4. HTTPS панели автоматически обслуживается на порту 443; продление полностью автоматическое

### Контроль доступа

Панель управления → Переключатели → **Разрешить доступ к пользовательской панели по IP / другим доменам**:

- ВКЛ (по умолчанию): панель доступна с любого адреса
- ВЫКЛ: доступ с неофициальных доменов и IP перенаправляется на официальный домен панели; `/admin`, `/api/*`, `/docs` и путь проверки ACME остаются доступными с любого адреса, чтобы вы никогда не заблокировали себя

### Обновление

```bash
cd WGTemporaryEmail
git pull
docker compose build
docker compose up -d
```

### Удаление

```bash
docker compose down -v   # -v также удаляет все данные почты
```
